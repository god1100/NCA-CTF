# 3. System Architecture

The architecture should have **four separate layers**.

```text
                     INTERNET / LAN
                           │
                           ▼
                 ┌───────────────────┐
                 │   CTF WEB APP     │
                 │                   │
                 │ Auth              │
                 │ Teams             │
                 │ Challenges        │
                 │ Leaderboard       │
                 │ Admin             │
                 └─────────┬─────────┘
                           │
                  ┌────────┴─────────┐
                  │                  │
                  ▼                  ▼
           ┌─────────────┐    ┌──────────────┐
           │  DATABASE   │    │ INTEGRITY    │
           │             │    │ ENGINE       │
           └─────────────┘    └──────┬───────┘
                                     │
                                     ▼
                           ┌──────────────────┐
                           │ CHALLENGE LAYER  │
                           │                  │
                           │ Docker Web       │
                           │ Docker Pwn       │
                           │ Downloadables    │
                           └──────────────────┘
```

The important boundary is:

```text
CTF Application ≠ Vulnerable Challenge
```

# 28. Network Isolation

This is extremely important.

Don't do:

```text
Docker
│
├── CTF
├── Database
├── Web vulnerable container
└── Pwn vulnerable container
```

with unrestricted communication.

Instead:

```text
                    CTF Network
                         │
              ┌──────────┴──────────┐
              │                     │
          CTF App                Database
              
              
                 Challenge Network
                         │
              ┌──────────┼──────────┐
              │          │          │
           Web01       Web02      Pwn01
```

Challenge containers should have **only the network access they actually need**.

# 30. Important Anti-Cheat Rule

**The system should never automatically disqualify a team solely based on an algorithm.**

Instead:

```text
Algorithm
   ↓
Suspicion
   ↓
Evidence
   ↓
Admin
   ↓
Decision
```

This prevents false positives.

For example:

> Ten students sharing the same NCA Wi-Fi doesn't mean they're cheating.

# 41. MonkeyCode Development Strategy

This is extremely important.

We should **not give MonkeyCode this entire document and say "build it."**

Instead, we'll create a series of controlled implementation prompts.

For example:

### Prompt 01

> Build the project foundation according to the architecture specification. Do not implement authentication, challenges, teams, or admin functionality yet.

Then test it.

### Prompt 02

> Implement the database schema...

Test.

### Prompt 03

> Implement authentication...

Test.

And so on.

Each prompt will tell MonkeyCode:

* What to implement
* What files it may modify
* What it must not modify
* Security requirements
* Expected behavior
* Acceptance criteria

This dramatically reduces AI-generated spaghetti code.
