# 1. Project Overview

The **NCA Batch 4 Private CTF Platform** will be a private, team-based Capture-the-Flag platform designed specifically for students participating in the NCA Batch 4 cybersecurity training program.

Unlike the existing public NCA CTF platform, which is intended for experienced penetration testers and competitive players, this platform will provide a **controlled environment specifically for Batch 4 students**.

The platform will allow participants to:

* Register and authenticate securely
* Join or create teams
* View available challenges
* Solve Web, Pwn, Crypto, General/Misc and other categories
* Submit flags
* Track their progress
* Compete on a real-time leaderboard
* Receive announcements
* View team statistics

Administrators will have a dedicated management interface to:

* Manage participants
* Manage teams
* Create and manage challenges
* Manage flags and scoring
* Monitor submissions
* Monitor challenge infrastructure
* View activity logs
* Detect suspicious activity
* Investigate potential flag sharing
* Warn or disqualify teams
* Manage the competition

The platform should be designed so that the **CTF application and vulnerable challenge infrastructure are isolated from each other**.

# 11. Flag System

Flags must never be exposed to normal users.

Instead of storing:

```text
NCA{secret_flag}
```

directly for validation, the system should preferably maintain a secure representation such as:

```text
SHA-256(flag)
```

Submission process:

```text
Student enters flag
       ↓
Normalize input
       ↓
Hash submitted flag
       ↓
Compare with stored hash
       ↓
Correct?
   ┌───┴────┐
   │        │
 YES       NO
   │        │
Score      Log
Update
```

# 15. Anti-Cheat / Integrity System

This should be one of the major features of the project.

The system should **not automatically ban someone based on one signal**.

Instead, it should generate an integrity alert.

### Signals

The platform can monitor:

* Identical flags submitted by multiple teams
* Extremely close solve timestamps
* Suspicious submission patterns
* Shared IP addresses
* Shared session characteristics
* Unusual solve sequences
* Rapid solving across many challenges
* Repeated suspicious interactions

---
