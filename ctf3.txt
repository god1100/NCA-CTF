# NCA Batch 4 Private CTF

## UI/UX Master Specification — V1.0

**Project:** NCA Batch 4 Private CTF Platform
**Audience:** NCA Batch 4 cybersecurity students and NCA administrators
**Design goal:** Professional cybersecurity competition platform
**UI direction:** Dark, technical, modern, competitive — but clean and readable.

---

# 1. Overall Design Direction

The platform should feel like a **professional CTF platform**, not a generic student dashboard.

The visual language should communicate:

> Cybersecurity + Competition + Technical + Professional

### Design characteristics

* Dark-first interface
* High contrast
* Clean cards
* Minimal gradients
* Monospace typography for technical information
* Clear challenge categories
* Strong status indicators
* Responsive layout
* Subtle animations
* No excessive neon effects
* No unnecessary glassmorphism everywhere

The interface should be visually inspired by professional security tooling and CTF platforms, **without copying another platform's UI**.

### ⬜ Final: MonkeyCode implementation prompts

Only after the above is frozen.

---

## The next thing I recommend we design

**The ERD/database in detail.**

This is the foundation that everything else depends on. We'll define **every table, column, datatype, primary key, foreign key, unique constraint, indexes, relationships, and important security considerations**, then produce the actual SQL schema.

After that, we'll design the **Docker challenge architecture**, including how you can create a Web/Pwn challenge locally with no VPS and later move the exact challenge to a VPS.

That gives us a solid chain:

**UI → ERD → Database → API → Docker → Integrity → MonkeyCode prompts → Implementation.**
